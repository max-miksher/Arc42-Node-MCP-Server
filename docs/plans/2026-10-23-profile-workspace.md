# Конструкция

План исполнен 2026-10-23. Текущий контракт: [product profile](../reference/product-profile.md); проверенный результат: [отчёт](../reports/profile-compatibility.md).

Основание: [требование](../requirements/2026-10-23-profile-workspace/описание.md).

Выбор исполнителя: расширить текущий реестр tools и использовать уже установленные Zod и YAML. Новый профиль хранит только раскладку и настройки в `.arc42.yaml` в корне проекта. Документы остаются единственным источником содержания. Старый `arc42-docs/config.yaml` сохраняет своё значение для старого режима. Проект с обоими форматами конфигурации отклоняется как неоднозначный.

Альтернативы: переписать сервер целиком (теряется простота обновления upstream); конвертировать всё в прежние 12 файлов (теряется адресуемость). Выбрано добавление профиля с ограниченными изменениями существующих обработчиков.

Новый `arc42-init` с `profile: product` создаёт конфигурацию, индекс docs, исходный requirement и минимальный Level 1. Остальные разделы создаются по потребности; полный scaffold включается явно. Пустые каталоги и документы не создаются. Неизвестное архитектурное содержание не выдумывается; черновики явно помечаются.

Новые инструменты: `arc42-document` (read/create/edit), `arc42-validate`, `arc42-inventory`, `arc42-migration-plan`. `get-section`, `update-section`, `arc42-status` читают новую раскладку при наличии `.arc42.yaml`. Точечная правка требует SHA-256 прочитанного файла и единственного exact-match; запись атомарна, конфликт версии не меняет файл. Запись сериализуется файловым lock; пути не могут выходить за корень или проходить через symlink.

Проверка синтаксиса и ссылок не доказывает истинность архитектуры относительно кода. Семантические конфликты выносятся владельцу. Миграция возвращает план в рамках указанного requirement и выбранных исходников, без копирования и удаления.

# Шаги

1. Зафиксировать baseline, лицензии и fork/upstream. Коммит требования и плана.
2. RED: интеграционные тесты инициализации, произвольной раскладки, чтения, безопасной правки, symlink/traversal и повторной инициализации. Реализовать общий workspace и подключение старых tools. GREEN, коммит.
3. RED: вложенные блоки, runtime, MADR, даты/статусы/ссылки/superseded и legacy-инвентаризация. Реализовать проверки и планирование. GREEN, коммит.
4. Проверить stdio MCP для нового и старого режима. Обновить Skill и установку. Сборка, полный suite, coverage, package dry-run. Коммит.
5. Отдельные Validator и Critic; исправления с RED→GREEN; holistic audit по требованию, профилю и upstream. Зафиксировать отчёт и отправить ветку в собственный форк.

# Проверки

`npm run build`; `npm test -- --run`; `npm run test:coverage -- --run`; `npm pack --dry-run`.

Review focus: сбои записи и конкурентные изменения; скрытые symlink; неоднозначная конфигурация; ссылки на неактивные документы; ложные обещания проверки содержательной согласованности; отсутствие автоматической миграции.
