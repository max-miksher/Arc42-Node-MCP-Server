# Совместимость

| Область | Реализация и граница |
|---|---|
| Arc42 | Все 12 разделов при новом init, конфигурируемые docsDir/sections, отдельные принадлежащие разделам подразделы |
| Building Blocks | Рекурсивные blackbox/whitebox-страницы, явные родители; произвольные локальные trigger/evidence-правила удалены |
| Runtime | Отдельные сценарии с явными ссылками на Building Blocks; участник не подменяется обзором всей системы |
| Раздел 1 | Архитектурный контекст и ссылки на внешние требования, без создания или ведения требований |
| Раздел 9 | Обзор архитектурных решений, влияние и краткое обоснование, ссылки на внешние ADR |
| Раздел 10 | Сценарии качества arc42 сохранены; внешние требования не управляются |
| ADR/MADR | Генерация, редактирование, проверка структуры, номеров и статусов удалены; ссылки проверяются как обычные адреса |
| C4 и Diátaxis | Нет редакторов, схем или правил; C4-генераторы удалены из встроенных примеров диаграмм |
| Планы | Нет инструментов управления; прежний arc42-migration-plan удалён |
| YAML | Обязателен для управляемых arc42-страниц product-режима; внешним документам не навязывается |
| Правки | Read → SHA-256 → единственное точное совпадение → проверка → временный файл → повторный hash → atomic rename |
| Legacy | Инвентаризация и чтение одного выбранного источника с hash, лимитами и пагинацией; перенос возможен только отдельной проверенной правкой arc42 |
| Upstream | Шесть исходных MCP-инструментов, 11 языков, Markdown/AsciiDoc, история и vendor submodule сохранены |

[Официальный раздел 5](https://docs.arc42.org/section-5/) описывает иерархию
blackbox/whitebox; глубина выбирается по архитектурной значимости.
[Раздел 6](https://docs.arc42.org/section-6/) связывает поведение с блоками системы.
[Раздел 9](https://docs.arc42.org/section-9/) допускает несколько форм представления
решений; обзор со ссылками — выбранная владельцем граница этого сервера.
YAML и расположение файлов являются соглашениями хранения форка, не универсальными
требованиями arc42. Требования других методологий не выдаются за правила arc42.

# Верификация

Команды: `npm run build`, `npm test -- --run`, `npm run test:coverage -- --run`,
`npm pack`, проверка установки tarball и загрузки собранного сервера.
Coverage-команда сначала собирает dist, поэтому stdio-тесты включены в этот прогон.
Финальная сборка TypeScript и полный suite прошли: **1369 тестов в 27 файлах**,
без пропусков. Независимый reviewer повторил полный suite с тем же результатом.
Покрытие: statements 94,39%, branches 85,33%, functions 99,28%, lines 97%.
Пороговые проверки покрытия пройдены. `git diff --check` не нашёл ошибок.

Проверен фактический tarball (315 файлов) и все его локальные Markdown-ссылки:
битых целей нет. Пакет установлен в отдельный временный каталог с production
зависимостями. Установленный dist/index.js через настоящий stdio MCP прошёл:
initialize, tools/list (10 tools), полный RU scaffold, get-section, правку с hash,
валидацию, ограниченное чтение legacy и отказ записи внешнего плана. Источник
legacy после этих операций неизменен. После финальной правки отчёта tarball
пересобран; runtime и зависимости совпадают с проверенным пакетом.

# Ограничения и обновления

Машинная проверка не доказывает истинность архитектуры или согласованность с кодом.
Она проверяет структуру, метаданные arc42, адресуемость ссылок и явные отношения.
Внешние HTTP URL, C4-нотация, структуры ADR, требований и планов не валидируются.
Если принадлежность подраздела удалена или повреждена до нераспознаваемости,
проверь unassignedFiles и восстанови section. Усечённый скан не считается успешным.

Lock координирует процессы сервера. Сторонний редактор не обязан учитывать lock;
CAS проверяет файл до atomic rename, но не исключает все внешние гонки.
Upstream replace/force сохраняет прежнюю семантику полной перезаписи; новые
безопасные точечные правки применяются в product-режиме. Прежние minimal-конфигурации
читаются, но повторный init не преобразует и не дополняет их автоматически.

Код распространяется по Apache-2.0; адаптированные arc42-шаблоны остаются
CC BY-SA 4.0 с attribution. LICENSE, LICENSE-ARC42 и NOTICE сохранены и поставляются
в пакете. Копии внешних методологий не добавлены. Original vendor submodule не изменён.
Upstream remote и история позволяют получать обновления; конфликты встроенных
шаблонов и обработчиков необходимо проверять при merge обновлений.

Никакая существующая документация пользователя автоматически не перенесена,
не переписана и не удалена. PR остаётся тем же; merge не выполняется.
