# Конфигурация и пути

`.arc42.yaml` в корне документируемого проекта — единственный источник физической раскладки. Содержимое документов хранится только в `.md`. Не создавай рядом альтернативный `arc42-docs/config.yaml`: сервер отклоняет неоднозначный проект.

`arc42-init` принимает profile: product, docsDir (по умолчанию docs), scaffold: minimal/full и sections — частичную карту исходных arc42 section ID в относительные `.md` пути. Инициализация сохраняет полную карту 12 разделов, язык и ссылку на версию arc42. Карта не означает, что каждый документ уже создан. requiredSections задаёт разделы, обязательные при проверке; Level 1 исключить нельзя. Остальные разделы появляются по потребности. После ручного изменения конфигурации каждый вызов проверяет её заново.

Пустой проект получает индекс, requirement с нормализованным заданием на создание документации и черновик Level 1. Full создаёт 12 непустых шаблонов-черновиков; это явный выбор scaffolding, а не подтверждение готовности архитектуры. Сценарии, ADR, блоки, диаграммы и Diátaxis-каталоги заранее не создаются.

Стабильные ID разделов сохраняют имена upstream (`08_concepts`, `11_technical_risks`); имена файлов профиля могут быть другими. `get-section` возвращает корневой документ раздела. Для вложенного файла используется arc42-document с путём относительно docsDir. Настройки language/format по-прежнему действуют в старом режиме; product всегда использует Markdown, шаблоны разделов доступны на 11 языках.

# Метаданные и связи

Каждый Markdown в docsDir начинается с YAML: title, type, status, updated. Допустимые type: architecture, adr, requirement, how-to, reference, tutorial, explanation, note, plan, index, policy. Status: draft, active, deprecated, superseded. updated — реальная календарная дата YYYY-MM-DD, не позже текущей UTC-даты сервера.

Связи related/requirements/blocks — непустые списки путей относительно docsDir. requirements указывает на документы type: requirement. superseded_by — путь к замене; требует status: superseded, существующий документ и отсутствие циклов. code — путь или список путей относительно корня репозитория. Символы кода не разрешаются автоматически: для них используй обычный текст Implementation и проверяй вручную.

Запросы располагаются в requirements/YYYY-MM-DD-slug/; каждый запрос содержит описание.md. Блоки имеют kind: building-block и parent; внутренние уровни имеют decomposition.trigger 1..5 и evidence. Runtime имеет kind: runtime-scenario и blocks, ссылающийся на реальные блоки. ADR отдельный; MADR minimal 4.0 сохраняет три смысловых раздела. Адаптер требует date и decision_status, чтобы отделить дату/состояние решения от updated/status документа; decision-makers необязателен. Эти дополнительные поля — выбор адаптера, а не универсальное требование MADR. Английские названия MADR-разделов используются как стабильные ключи; тело допускает любой язык.

Диаграммы C4 можно хранить рядом с разделом и связывать обычными Markdown-ссылками. Сервер проверяет локальный путь к диаграмме, но не её синтаксис и архитектурное содержание. Requirements, Diátaxis, notes и plans остаются отдельными категориями, не подмешиваются в arc42.

# Запись

Create не перезаписывает существующий файл. Edit требует SHA-256 из read и ровно одно exact-match совпадение oldText. Допускается пустой newText. Новый результат должен проходить проверки метаданных и явных связей. Чтение повреждённого Markdown разрешено и возвращает metadataError для ремонта без потери содержания. updated поддерживает автор правки: если меняется дата документа, включи её в патч.

Запись проходит под общим файловым lock, в новый временный файл и через atomic rename. Hash перепроверяется перед заменой. MCP-процессы, использующие этот lock, не теряют совместные изменения. Внешний редактор не участвует в lock: синхронная запись ровно между последней проверкой и rename остаётся ограничением файлового compare-and-swap. Проверка путей не является защитой от процесса, который злонамеренно меняет дерево каталогов во время записи.

# Проверка и инвентаризация

arc42-validate проверяет весь docsDir: обязательные разделы, frontmatter, календарные даты, типы/роли, локальные Markdown-ссылки и anchors, отдельные MADR, родителей блоков, участников runtime, ссылки code/requirements, цепочки superseded. Word count не считается полнотой. Черновики и непроверенное обоснование decomposition возвращаются предупреждениями.

Внешние URL не запрашиваются. Содержательная истинность, качество C4, фактическое выполнение триггера углубления, соответствие коду и отсутствие смысловых противоречий требуют review. Структурный valid=true не разрешает заявлять, что архитектура проверена содержательно.

Сканирование ограничено maxFiles (бюджет посещённых файлов и каталогов), maxBytes (размер отдельного документа) и maxDepth. Значения по умолчанию: 5000, 2 000 000 байт, 32. Превышение явно выставляет truncated; неполная валидация не считается успешной. Symlink не обходятся. Inventory пропускает .git, node_modules, vendor, dist, build, coverage и .superpowers; валидатор не исключает документы внутри настроенного docsDir по этим именам.

arc42-inventory умеет читать проект до init. Он возвращает хеши, точные дубли, ошибки метаданных и эвристические suggestedType. Ни одно предложение не делает legacy нормативным. arc42-migration-plan требует текущее requirement, конкретные source/target/reason и возвращает снимок хешей. Он ничего не записывает. Перенос, изменение статуса и устранение конфликта выполняются отдельной осмысленной правкой.

Хеш и размер legacy вычисляются по исходным байтам. Неизвестная кодировка отмечается encoding: unknown; сервер не конвертирует её автоматически и не считает такие материалы точными дублями по тексту с заменёнными символами.
